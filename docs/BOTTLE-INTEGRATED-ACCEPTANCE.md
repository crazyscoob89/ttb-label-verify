# Bottle repair: integrated local acceptance

## Release boundary

This integrates the bounded semantic repair and `bottle-photo-clarity-r1` extraction prompt into the existing client, not a UI redesign or a new evidence contract. Fresh singletons are revision 5; fresh groups are revision 6 / `photo-set-aggregation-v2`. Live execution rejects all other pairs before rendering. Saved readers retain exact replay of singleton 1/2/3 and group 4/v1, alongside fresh 5/6; no saved records are rewritten.

Backend and UI photo fixtures are regenerated by the existing real-comparator scripts. Frozen `semantic-history.json`, `rules-v1-records.json`, rules 1/2/3 and SQL003 remain unchanged.

## Incident regression provenance

`tests/fixtures/bottle-incident.ts` preserves the reported full uppercase warning as a literal, separate from the evaluator reference. It refines the original reconstructed incident scaffold without changing its historical fixtures: the actual paste lists both views as net-contents sources. The paste is not original provider JSON; absent raw per-photo ABV/body reasons and commodity/import flags are explicitly reconstruction assumptions.

`tests/photo-route.test.ts` drives real `prepareLiveGroup` / `executeLiveGroup` → authenticated multipart route → intake / normalization → guarded extraction adapter → comparison / snapshot boundary → strict browser-client replay. Provider transport and snapshot storage in this unit test are mocks; global external fetch throws. The separate existing durable browser suite supplies real SQLite save/restart/history/media coverage.

The incident regression establishes:
- Tequila Gold is compatible with broad Tequila without erasing the specific observed designation.
- Spanish/English explicit Mexico origin prefixes agree with individual provenance.
- Whole-warning-in-heading projection splits only the supplied text; raw heading and missing raw body are unchanged, with explicit source-path derivation.
- Uppercase warning body is case-insensitively equivalent; exact heading case/colon and visible boldness remain independently required. Unknown body boldness and physical size remain unverified.
- Misidentified/uncertain producer roles are not forced green; the reported unreadable ABV is not filled from the application.
- A differently named fictional bottle, Cerro Claro / Destileria del Valle, exercises the same rules and rejects unsupported origin statements, incompatible class/subtype, changed warning words/heading/boldness and unrelated importer substitution.

The optional `TTB_BOTTLE_GROUND_TRUTH=/absolute/path/to/ttb-jose-cuervo-ground-truth.json` gate reads the exact front/back JPEGs referenced by that local document. It verifies source byte counts and SHA-256, plus the original incident-paste hash, and runs both reconstructed-incident and independent-inspection-style mock observations through the real route/client. Images are not committed. Inspection-style readable 40% and separated uppercase warning match; producer uncertainty and physical-size review remain. **This is not evidence that a live model reads those photos correctly.**

## Reproduction

From `web`, use Node24, `NODE_OPTIONS=--max-old-space-size=512`, one worker, and the lockfile dependencies:

```sh
node --import tsx scripts/generate-photo-fixtures.ts
node --import tsx scripts/generate-photo-ui-fixtures.ts
node node_modules/vitest/vitest.mjs run --maxWorkers=1 --testTimeout=30000
node node_modules/typescript/bin/tsc --noEmit --incremental false
NEXT_TELEMETRY_DISABLED=1 npm run build
```

For the actual additive SQL gate, configure only disposable local Unix-socket `TTB_HOSTED_TEST_SOCKET`, `TTB_HOSTED_TEST_PORT`, `TTB_HOSTED_TEST_PSQL`, then run `tests/photo-postgres.test.ts` and `tests/semantic-migration.test.ts`. The test checks 003 rejects 6/v2, applies actual SQL004 under the same local owner, admits historical 4/v1 and fresh 6/v2, rejects crossed/unknown/null versions, preserves existing snapshots, function ownership/ACLs and ledger values, and retains existing strict assets, quotas, concurrency and restricted-role checks. The SQL is not replaced with an emulation.

Browser and real-route durable commands/environment are in `MULTIPHOTO-LOCAL-ACCEPTANCE.md`. API-mocked browser tests and the guarded synthetic-provider durable test are distinct evidence categories. The durable test requires a completed production build and proves fresh group receipts survive a different-PID restart, historical singleton records stay unchanged, all private media hashes agree, and no provider call occurs on history reopening.

## Hosted readiness and performance limits

Production remains the existing Supabase project; SQL003 is already deployed. Parent release review must approve the exact SHA and apply only SQL004 under the existing approved migration owner before deploying fresh writers. No new project, infra rebuild, source publication, hosted migration or deployment is part of this local work.

The supplied incident timing was 13.449 seconds, with 11.674 seconds for combined comparison/snapshot—not a model-only measurement. Prior offline profile artifacts remain outside Git and unchanged. Local mocked adapter milliseconds do not establish live speed or a five-second achievement. A separately approved, budget-guarded exact-photo live validation remains required after review; no paid calls are part of this acceptance. Hosted Verify-access latency, managed Storage behavior and real OCR/producer-role accuracy are not certified by local tests.
